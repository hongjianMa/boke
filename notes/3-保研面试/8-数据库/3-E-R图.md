# E-R 图

## E-R 图概念

E-R 图，全称 **实体-联系图（Entity-Relationship Diagram）**，主要用于数据库的**概念结构设计**。

E-R 图主要由三部分组成：

- **实体（Entity）**
- **属性（Attribute）**
- **联系（Relationship）**

------

## 二、E-R 图的基本元素

### 1. 实体

表示现实世界中客观存在、可以相互区分的事物。

例如：

- 学生
- 课程
- 教师
- 学院

**表示方法：矩形。**

```
┌──────┐
│ 学生 │
└──────┘
```

------

### 2. 属性

表示实体所具有的特征。

例如学生实体具有：

- 学号
- 姓名
- 性别
- 专业

**表示方法：椭圆，并与对应实体连接。**

```
        学号
         ○
         |
姓名 ○——学生——○ 专业
```

关系模型中，属性通常对应关系表中的**字段/列**。

------

### 3. 联系

表示不同实体之间的关系。

例如：

```
学生 —— 选课 —— 课程
```

其中“选课”就是联系。

**表示方法：菱形。**

------

# 实体之间的联系类型

主要有三种：

1:1,1:N,M:N

分别表示：

- 一对一
- 一对多
- 多对多

------

## 一对一关系 1:1

### 含义

一个 A 实体最多对应一个 B 实体，一个 B 实体也最多对应一个 A 实体。

例如：

```
人 1 —— 1 身份证
```

### 转换为关系模型

> **任选一端，把另一端的主键加入作为外键。**

例如：

```
Person(
    PersonId,
    Name,
    CardId
)
IDCard(
    CardId,
    Address
)
```

其中 `CardId` 可以作为 `Person` 表中的外键。

### 记忆

> **1:1：任选一边放。**

------

# 一对多关系 1:N

### 含义

一个 A 可以对应多个 B，但一个 B 只能对应一个 A。

例如：

```
学院 1 —— N 学生
```

一个学院有多个学生，一个学生只属于一个学院。

------

## 转换为关系模型

> **把“一端”的主键放到“多端”，作为外键。**

例如：

```
Department(
    DeptId,
    DeptName
)
Student(
    Sno,
    Sname,
    DeptId
)
```

其中：

- `DeptId` 是 Department 的主键。
- `DeptId` 是 Student 的外键。

### 记忆

> **1:N：主键往 N 端放。**

------

## 联系本身有属性

如果 1:N 联系本身还有属性，一般也放到 **N 端**。

例如：

```
部门 1 —— N 员工
```

联系中还有“入职时间”。

可以设计：

```
Employee(
    EmployeeId,
    Name,
    DeptId,
    JoinTime
)
```

也就是：

> **N 端 = 自己的属性 + 1 端主键 + 联系属性。**

------

# 多对多关系 M:N

### 含义

一个 A 可以对应多个 B，一个 B 也可以对应多个 A。

典型例子：

```
学生 M —— N 课程
```

一个学生可以选择多门课程，一门课程也可以被多个学生选择。

------

## 转换为关系模型

多对多关系不能简单地把某一端主键放到另一端。

正确方法：

> **把联系单独转换成一张新表。**

新表包括：

1. 两端实体的主键。
2. 联系本身的属性。

例如：

```
Student(
    Sno,
    Sname
)
Course(
    Cno,
    Cname
)
```

新建选课表：

```
SC(
    Sno,
    Cno,
    Grade
)
```

其中：

- `Sno` 来自 Student。
- `Cno` 来自 Course。
- `Grade` 是“选课”联系自己的属性。

通常：

(Sno,Cno)

共同组成 `SC` 的主键。

### 记忆

> **M:N：单独建表，两边主键都拿过来。**

------

# 为什么 M:N 要单独建表

假设直接设计：

| Sno  | Sname | Cno         |
| ---- | ----- | ----------- |
| 001  | 张三  | C01,C02,C03 |

这里 `Cno` 一列存了多个值，不满足 **1NF 的属性原子性**。

因此应改为：

| Sno  | Cno  |
| ---- | ---- |
| 001  | C01  |
| 001  | C02  |
| 001  | C03  |

所以：

> **多对多关系通常必须通过中间表实现。**

------

# 三种联系的转换规则

| 联系类型 | 转换规则                           |
| -------- | ---------------------------------- |
| **1:1**  | 任意一端加入另一端主键作为外键     |
| **1:N**  | 1 端主键加入 N 端作为外键          |
| **M:N**  | 新建关系表，加入两端主键和联系属性 |

最重要的口诀：

> **一对一随便放，一对多放多端，多对多单独建表。**

------

# 完整例子

存在：

```
学院 1 —— N 学生


学生 M —— N 课程
```

可以转换为：

### 学院表

```
Department(
    DeptId,
    DeptName
)
```

### 学生表

```
Student(
    Sno,
    Sname,
    DeptId
)
```

由于：

```
学院 1 —— N 学生
```

所以：

> 学院主键 `DeptId` 放进学生表。

------

### 课程表

```
Course(
    Cno,
    Cname
)
```

### 选课表

```
SC(
    Sno,
    Cno,
    Grade
)
```

由于：

```
学生 M —— N 课程
```

所以：

> 单独创建 `SC` 选课表。
