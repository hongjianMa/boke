# 头指针和头结点的区别？
**头指针**是一个指针变量，用来保存链表第一个结点的地址，是访问链表的入口。
 **头结点**是链表中人为添加的一个结点，通常放在第一个有效数据结点之前，一般不存放有效数据，主要是为了统一插入、删除等操作。

例如：

```
head
 ↓
[头结点] → [结点1] → [结点2] → NULL
```

这里 `head` 是头指针，`[头结点]` 是头结点。

面试时还可以补一句：**链表可以没有头结点，但一定需要一个指针来找到链表；如果带头结点，那么头指针通常指向头结点；如果不带头结点，头指针就直接指向第一个有效数据结点。**

一句话总结：**头指针是“指针”，负责定位链表；头结点是“结点”，负责简化链表操作。**

# 循环队列Q中元素的个数计算？
循环队列中元素个数的经典计算公式是：

$\boxed{(rear-front+MaxSize)\%MaxSize}$

其中：

- `front`：队头指针；
- `rear`：队尾指针；
- `MaxSize`：循环队列数组的最大容量。

之所以不能直接用 `rear - front`，是因为循环队列中 `rear` 可能绕到 `front` 前面。

例如 `MaxSize = 10`：

```
front = 2
rear  = 7
```

元素个数：

$(7-2+10)\%10=5$

如果发生了循环：

```
front = 7
rear  = 2
```

那么：

$(2-7+10)\%10=5$

### 面试回答

可以直接回答：

> 对于数组实现的循环队列，如果 `front` 指向队头元素，`rear` 指向队尾元素的下一个位置，那么队列中的元素个数为：
>
> (rear−front+MaxSize)%MaxSize(rear-front+MaxSize)\%MaxSize
>
> 加上 `MaxSize` 再取模，是为了处理 `rear` 已经循环到 `front` 前面的情况。

顺便记住循环队列最常考的三个公式：

$\boxed{\text{元素个数}=(rear-front+MaxSize)\%MaxSize}$$\boxed{\text{队空：}front=rear}$

如果采用**牺牲一个存储单元**的方法判断队满：

$\boxed{\text{队满：}(rear+1)\%MaxSize=front}$

因此这种实现中，数组长度虽然是 `MaxSize`，但最多只能存 **`MaxSize-1` 个元**

# 如何区分循环队列是队空还是队满？
循环队列中，**仅看 `front == rear` 是无法同时区分“队空”和“队满”的**，因为如果所有数组空间都允许使用，队空和队满时都可能出现 `front == rear`。

面试中最常见的是采用**牺牲一个存储单元**的方法：

- **队空：**

  front=rear\boxed{front=rear}

- **队满：**

  (rear+1)%MaxSize=front\boxed{(rear+1)\%MaxSize=front}

例如数组长度 `MaxSize = 5`：

```
队空：
front = 2
rear  = 2

队满：
front = 2
rear  = 1

因为：
(rear + 1) % 5
= (1 + 1) % 5
= 2
= front
```

这种方法虽然数组有 `MaxSize` 个位置，但只能存：

$\boxed{MaxSize-1}$

个元素。

### 面试怎么回答

> 循环队列中，为了区分队空和队满，通常会牺牲一个存储单元。规定 `front == rear` 表示队空，而 `(rear + 1) % MaxSize == front` 表示队满。这样虽然浪费了一个数组位置，但是判断非常简单。

另外还可以采用其他方法，例如增加一个 `size` 变量记录当前元素个数：

$size=0 \Rightarrow 队空$$size=MaxSize \Rightarrow 队满$

或者增加一个标志位 `tag`，记录最后一次操作是入队还是出队。但**数据结构考试和面试最常见的答案就是“牺牲一个存储单元”**。


# 哈希表的概念、构造方法、哈希冲突的解决办法？
面试中这题可以按照 **“概念 → 构造方法 → 冲突解决”** 来回答。

### 1. 哈希表的概念

**哈希表（Hash Table）\**是一种通过\**哈希函数**，把关键字 `key` 直接映射到数组下标，从而快速进行查找的数据结构。

基本思想是：

$\boxed{地址 = Hash(key)}$

比如：

```
key = 25
Hash(key) = 25 % 10 = 5
```

那么就把 `25` 存到数组下标 `5` 的位置。

理想情况下，哈希表的插入、删除、查找的平均时间复杂度都是：

$\boxed{O(1)}$

但是不同的 `key` 可能通过哈希函数得到相同的位置，这种情况叫做**哈希冲突**。

例如：

```
Hash(key) = key % 10

25 % 10 = 5
35 % 10 = 5
```

`25` 和 `35` 都想存到下标 `5`，这就是哈希冲突。

------

### 2. 常见哈希函数构造方法

最常见的是**除留余数法**：

$\boxed{Hash(key)=key\%p}$

其中 `p` 一般选择一个合适的质数，并且通常满足：

$p \leq 表长$

例如：

```
Hash(key) = key % 13
```

此外，还有直接定址法、数字分析法、平方取中法、折叠法等。

面试里通常重点回答：**最常用的是除留余数法，将关键字对一个合适的质数取模，从而得到哈希地址。**

------

### 3. 哈希冲突的解决方法

主要有两大类：**开放定址法**和**链地址法**。

#### 开放定址法

发生冲突以后，在哈希表中寻找其他空位置。

最典型的是**线性探测法**。

比如：

```
Hash(25) = 5
Hash(35) = 5
```

`25` 已经占据下标 `5`，那么 `35` 就依次向后找：

```
5 → 6 → 7 → 8 → ...
```

找到第一个空位置后存入。

公式可以表示为：

$\boxed{H_i=(H(key)+i)\%m}$

其中 `m` 是哈希表长度。

除了线性探测，还有**二次探测**：

$H_i=(H(key)+i^2)\%m$

以及**双重哈希**，使用另一个哈希函数计算探测步长。

开放定址法的缺点是容易产生**聚集现象**，表越满，查找效率越低。

#### 链地址法

这是实际开发中非常常见的方法。

数组中的每个位置不直接只存一个元素，而是对应一条链表：

```
0
1
2
3
4
5 → 25 → 35 → 45
6
7
```

例如：

```
25 % 10 = 5
35 % 10 = 5
45 % 10 = 5
```

三个元素都映射到位置 `5`，那么就把它们放在同一条链表中。

它的优点是处理冲突比较简单，而且哈希表装得比较满时也比线性探测稳定。

------

### 面试标准回答

> 哈希表是一种根据关键字直接计算存储地址的数据结构，通过哈希函数把 key 映射到数组下标，因此理想情况下查找、插入和删除的平均时间复杂度都是 O(1)。
>  哈希函数最常见的构造方式是除留余数法，也就是 `Hash(key) = key % p`，其中 p 一般选择合适的质数。
>  由于不同的 key 可能得到相同的哈希地址，因此会产生哈希冲突。解决哈希冲突主要有开放定址法和链地址法。开放定址法包括线性探测、二次探测和双重哈希，而链地址法是把哈希值相同的元素放到同一条链表中。实际应用中链地址法比较常见。

再记一个面试高频概念：**装载因子**。

$\boxed{\alpha=\frac{哈希表中元素个数}{哈希表容量}}$

装载因子越大，发生哈希冲突的概率通常越高，因此哈希表通常会在装载因子达到一定阈值以后进行**扩容和重新哈希（rehash）**。

# 判断链表是否有环?
判断链表是否有环，面试中最经典的方法是**快慢指针，也叫 Floyd 判圈算法**。

设两个指针：

- `slow` 每次走 1 步。
- `fast` 每次走 2 步。

如果链表**没有环**，那么 `fast` 最终一定会走到 `nullptr`；如果链表**有环**，那么 `fast` 进入环后一定会追上 `slow`，两者最终相遇。

```
bool hasCycle(ListNode *head) {
    ListNode *slow = head;
    ListNode *fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;

        if (slow == fast) {
            return true;
        }
    }

    return false;
}
```

时间复杂度是：

$O(n)$

空间复杂度是：

$O(1)$

面试时可以这样回答：

> 判断链表是否有环，可以使用快慢指针。定义 `slow` 和 `fast` 两个指针，`slow` 每次走一步，`fast` 每次走两步。如果链表无环，`fast` 最终会走到空指针；如果链表有环，由于 `fast` 比 `slow` 走得快，两者进入环后最终一定会相遇。因此只要判断两指针是否相遇即可，时间复杂度 O(n)，空间复杂度 O(1)。

还有一种方法是使用 `unordered_set` 保存访问过的结点地址，如果某个结点再次出现，就说明存在环。这种方法时间复杂度也是 O(n)，但空间复杂度为 O(n)，所以面试中一般优先回答**快慢指针法**。

# 平衡二叉树、二叉排序树、完全二叉树、二叉搜索树的区别及构造？

这四个概念里，最容易混淆的一点是：

> **二叉排序树 = 二叉搜索树，英文都是 Binary Search Tree，BST。**

所以真正需要区分的主要是：**二叉搜索树、平衡二叉树、完全二叉树**。

### 1. 二叉排序树 / 二叉搜索树 BST

定义是：

对于任意一个结点：

- 左子树所有结点的值都小于该结点；
- 右子树所有结点的值都大于该结点；
- 左右子树本身也都是二叉搜索树。

例如：

```
        5
       / \
      3   8
     / \ / \
    2  4 6  9
```

它满足：

```
左边 < 根 < 右边
```

因此对 BST 进行**中序遍历**：

```
2 3 4 5 6 8 9
```

结果一定是有序的。

#### BST 怎么构造

按照数据出现的顺序依次插入。

例如：

```
5, 3, 8, 2, 4, 6
```

先插入 `5`：

```
5
```

插入 `3`，因为 `3 < 5`：

```
  5
 /
3
```

插入 `8`：

```
  5
 / \
3   8
```

继续插入后得到：

```
        5
       / \
      3   8
     / \ /
    2  4 6
```

插入规则一句话：

> **小于当前结点就往左走，大于当前结点就往右走，直到找到空位置。**

但是普通 BST 有一个明显问题。

如果插入：

```
1, 2, 3, 4, 5
```

会变成：

```
1
 \
  2
   \
    3
     \
      4
       \
        5
```

已经退化成链表，查找复杂度从理想的 `O(log n)` 退化成：

$O(n)$

------

### 2. 平衡二叉树

通常数据结构面试里说的**平衡二叉树**，主要指 AVL 树。

AVL 首先是一棵：

> **二叉搜索树。**

然后额外要求：

> 任意结点的左右子树高度差不能超过 1。

定义平衡因子：

$BF=左子树高度-右子树高度$

对于 AVL 树，每个结点必须满足：

$\boxed{|BF|\le 1}$

例如：

```
        5
       / \
      3   8
     / \   \
    2   4   9
```

这是平衡的。

但：

```
    5
   /
  4
 /
3
```

根结点左右子树高度差已经超过 1，所以不是平衡二叉树。

### 平衡二叉树怎么构造

AVL 的构造本质上是：

> **先按照 BST 的规则插入，然后检查是否失衡；如果失衡，通过旋转恢复平衡。**

主要有四种失衡情况：

| 类型 | 情况             | 调整           |
| ---- | ---------------- | -------------- |
| LL   | 左孩子的左边过高 | 右旋           |
| RR   | 右孩子的右边过高 | 左旋           |
| LR   | 左孩子的右边过高 | 先左旋，再右旋 |
| RL   | 右孩子的左边过高 | 先右旋，再左旋 |

例如插入：

```
30, 20, 10
```

开始：

```
    30
   /
  20
 /
10
```

这是 **LL 型失衡**。

对 `30` 进行右旋：

```
   20
  /  \
10   30
```

重新变成平衡二叉树。

所以 AVL 的查找、插入、删除一般都能维持：

$O(\log n)$

------

### 3. 完全二叉树

完全二叉树和前面的 BST、AVL **不是一个维度的概念**。

它不关心：

```
左边的值是否比根小
```

它只关心：

> **结点在树中的位置是否连续。**

完全二叉树要求：

- 除最后一层外，其他层全部放满；
- 最后一层如果没有放满，结点必须连续地从左向右排列。

例如：

```
        1
       / \
      2   3
     / \ /
    4  5 6
```

这是完全二叉树。

这个也是：

```
        1
       / \
      2   3
     /
    4
```

仍然是完全二叉树。

但是：

```
        1
       / \
      2   3
       \
        5
```

不是完全二叉树。

因为最后一层出现了：

```
左边空了，右边却还有结点
```

违反了从左到右连续排列。

### 完全二叉树怎么构造

完全二叉树通常按照**层序，从左向右**添加结点。

例如：

```
1, 2, 3, 4, 5, 6
```

依次放进去：

```
        1
       / \
      2   3
     / \ /
    4  5 6
```

因此完全二叉树非常适合使用数组存储。

假设数组下标从 `0` 开始，对于下标 `i`：

$左孩子=2i+1$$右孩子=2i+2$$父结点=\left\lfloor\frac{i-1}{2}\right\rfloor$

所以**堆 Heap 本质上就是一种完全二叉树**。

------

### 四个概念放一起比较

| 类型           | 核心要求             | 关注重点    | 是否有大小关系 |
| -------------- | -------------------- | ----------- | -------------- |
| 二叉排序树     | 左 < 根 < 右         | 元素大小    | 有             |
| 二叉搜索树     | 左 < 根 < 右         | 元素大小    | 有             |
| 平衡二叉树 AVL | BST + 左右高度差 ≤ 1 | 大小 + 高度 | 有             |
| 完全二叉树     | 按层从左到右连续排列 | 结点位置    | 没有要求       |

最关键的关系可以理解成：

```
二叉树
│
├── 二叉搜索树 BST
│      │
│      └── AVL 平衡二叉树
│
└── 完全二叉树
```

也就是说：

> **AVL 一定是 BST，但 BST 不一定是 AVL。**

而：

> **完全二叉树不一定是 BST，BST 也不一定是完全二叉树。**

例如：

```
        10
       /  \
      20   5
```

它可以是一棵完全二叉树，因为结点位置符合要求。

但它不是 BST，因为：

```
20 > 10
```

却出现在左子树。

### 面试标准回答

> 二叉排序树和二叉搜索树其实是同一个概念，也就是 BST。它要求任意结点的左子树都小于根结点，右子树都大于根结点，因此中序遍历结果是有序的。构造时按照“小的往左，大的往右”的规则依次插入。
>
> 平衡二叉树通常指 AVL 树，它是在二叉搜索树的基础上进一步要求每个结点左右子树的高度差不超过 1。如果插入后出现失衡，需要通过 LL、RR、LR、RL 四种旋转方式恢复平衡，从而使查找、插入等操作保持在 O(log n) 量级。
>
> 完全二叉树关注的不是结点值的大小，而是结点的位置。除了最后一层必须全部填满，最后一层的结点必须从左到右连续排列。完全二叉树非常适合使用数组存储，堆就是典型的完全二叉树。
