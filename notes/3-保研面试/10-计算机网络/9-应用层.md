# 应用层

## HTTP 超文本传输协议
用于规定客户端与服务器之间如何发送请求、返回响应。访问网页、提交表单、调用后端接口，通常都会用到 HTTP。它不仅能传输 HTML，还能传输 JSON、图片、音频等数据。

### 1. HTTP 的工作过程是什么？

以浏览器访问网站为例：

1. 通过 DNS 解析域名，获得服务器 IP 地址。
2. 建立连接；对于 HTTP/1.1 和 HTTP/2，通常建立 TCP 连接。使用 HTTPS 时，还需要进行 TLS 握手。
3. 浏览器发送 HTTP 请求。
4. 服务器处理请求，返回 HTTP 响应。
5. 浏览器解析响应并展示页面，连接可以复用，也可以关闭。

> 注意：**HTTP/3 基于 QUIC，QUIC 基于 UDP**，因此“HTTP 一定基于 TCP”并不准确。


### 简单介绍一下HTTP/1.0~HTTP/3.0？你了解QUIC协议吗？

**HTTP 各版本的演进，主要是为了提高连接复用能力、传输效率，并减少队头阻塞。**

| 版本         | 主要特点                                                     | 存在的问题                                                   |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **HTTP/1.0** | 默认使用短连接，每次请求响应后通常关闭 TCP 连接              | 频繁建立连接，开销较大                                       |
| **HTTP/1.1** | 默认使用长连接，多个请求可以复用 TCP 连接；支持管线化        | 管线化要求响应按请求顺序返回，前面的响应慢会阻塞后面的响应，存在 HTTP 层队头阻塞 |
| **HTTP/2**   | 引入**二进制分帧、多路复用、HPACK 头部压缩**，多个请求和响应可以在同一连接上交错传输 | 底层仍使用 TCP，丢包会导致同一连接上的多个流等待，存在 TCP 层队头阻塞 |
| **HTTP/3**   | 使用 **QUIC 替代 TCP**，通过独立流传输减少丢包对其他流的影响，使用 QPACK 头部压缩 | 部署需要网络环境支持 QUIC 的 UDP 通信                        |

**QUIC 是一种基于 UDP 的安全、可靠的传输协议，也是 HTTP/3 的底层协议。**虽然 UDP 本身不保证可靠性，但 QUIC 自己实现了确认、重传、流量控制和拥塞控制，因此不能把它理解为不可靠传输。

它的主要特点有：

1. **减少跨流队头阻塞**：不同流独立交付数据，一个流丢包不会因为必须等待该流重传而阻塞其他流，但丢包仍可能通过共享拥塞控制影响整体吞吐量。同一个流内部仍需按序交付。
2. **建立连接更快**：集成 TLS 1.3，首次连接通常需要 **1-RTT**，满足条件的恢复连接可以使用 **0-RTT** 提前发送数据；0-RTT 数据存在重放风险。
3. **支持连接迁移**：使用连接 ID 标识连接，网络从 Wi-Fi 切换到移动网络、IP 地址变化时，经过路径验证可以继续使用原连接。
4. **默认加密保护**：将安全握手与传输协议结合，保护应用数据。

面试可以简记为：**HTTP/1.0 是短连接，HTTP/1.1 默认长连接，HTTP/2 实现多路复用，HTTP/3 通过 QUIC 进一步解决 TCP 层的跨流队头阻塞；QUIC 基于 UDP，实现可靠传输，并支持快速握手、加密和连接迁移。**

## 简述HTTP和HTTPS的区别:
HTTPS 是在 HTTP 的基础上使用 TLS 提供安全保护的协议。主要区别如下：

| 对比项         | HTTP                  | HTTPS                          |
| -------------- | --------------------- | ------------------------------ |
| **数据传输**   | 明文传输              | 加密传输，防止窃听             |
| **完整性保护** | 本身不提供            | 能检测数据是否被篡改           |
| **身份认证**   | 本身不提供            | 通常通过数字证书验证服务器身份 |
| **默认端口**   | 80                    | 443                            |
| **性能开销**   | 无 TLS 握手和加密开销 | 增加 TLS 握手及加解密开销      |

面试可概括为：HTTP 主要规定数据如何交互，HTTPS 在此基础上增加了**加密、完整性保护和身份认证**，使通信更加安全。
